# Prompt, Context, Harness

이 문서는 세 개념의 차이를 분명하게 정리합니다.

## 1. 프롬프트 엔지니어링

프롬프트 엔지니어링은 `무엇을 원하는지 잘 설명하는 기술`입니다.

- 목표를 분명하게 말한다
- 제약을 명시한다
- 기대 결과를 구체화한다

핵심 질문:

- 내가 원하는 결과를 에이전트가 정확히 이해했는가

## 2. 컨텍스트 엔지니어링

컨텍스트 엔지니어링은 `에이전트가 일을 잘하는 데 필요한 배경과 히스토리를 잘 전달하는 기술`입니다.

- 저장소 구조를 보여 준다
- 관련 문서와 기존 결정을 연결한다
- 필요한 사실을 필요한 시점에 찾게 한다

핵심 질문:

- 에이전트가 지금 판단하는 데 필요한 맥락을 충분히, 그러나 과하지 않게 갖고 있는가

## 3. 하네스 엔지니어링

하네스 엔지니어링은 `에이전트가 실수해도 다시 돌아오게 만드는 실행 환경을 설계하는 일`입니다.

- 계획 없이 구현하지 못하게 한다
- 메인에서 바로 작업하지 못하게 한다
- 검증을 건너뛰지 못하게 한다
- 실패하면 원인을 볼 수 있게 로그와 증거를 남긴다

핵심 질문:

- 에이전트가 규칙을 잊거나 무시해도 시스템이 다시 올바른 경로로 되돌릴 수 있는가

## 차이 요약

- 프롬프트: 말을 잘하는 것
- 컨텍스트: 필요한 배경지식을 잘 공급하는 것
- 하네스: 잘못했을 때도 안전하게 일하게 만드는 것

## 이 저장소의 입장

좋은 하네스는 프롬프트를 대체하지 않습니다. 좋은 컨텍스트도 하네스를 대체하지 않습니다.

세 가지가 서로 보완되어야 합니다.

- 프롬프트만 좋고 하네스가 없으면, 잘 이해하고도 멋대로 틀릴 수 있습니다.
- 컨텍스트만 많고 구조가 없으면, 많이 주고도 읽히지 않을 수 있습니다.
- 하네스만 세고 목적 설명이 약하면, 규칙은 지키지만 쓸모없는 결과를 낼 수 있습니다.
