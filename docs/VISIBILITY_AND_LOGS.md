# Visibility and Logs

하네스가 제대로 작동하려면 에이전트가 자신의 결과를 볼 수 있어야 합니다.

이 문서는 `가시성 확보`를 위한 기본 규칙을 정의합니다.

## 왜 필요한가

- 사람이 매번 직접 테스트하고 화면을 보며 판정하면 병목이 된다
- 에이전트가 스스로 실패를 보고 수정하려면 실행 흔적이 남아야 한다
- 다음 실행도 같은 문제를 빠르게 재현하고 이해할 수 있어야 한다

## 남겨야 하는 증거

- 검증 명령 결과 요약
- 실패 로그
- UI 작업이면 스크린샷
- 필요 시 JSON 형태의 결과 파일

## 어디에 남기나

- 기본 위치는 `logs/`
- 장기 보관이 필요한 설계 수준 교훈은 `docs/`로 승격

## 무엇을 남기지 않나

- 너무 커서 읽히지 않는 원시 로그 전체
- 다시는 재사용하지 않을 임시 출력
- 민감 정보가 포함된 원본 그대로의 로그

## 권장 흐름

1. 검증 전에 어떤 증거를 남길지 정한다
2. 실패하면 `logs/`에 요약과 핵심 증거를 남긴다
3. 같은 실패가 반복되면 문서나 스크립트 규칙으로 승격한다

## 파일명 규칙

- `YYYY-MM-DD-task-slug-summary.log`
- `YYYY-MM-DD-task-slug-screenshot.png`
- `YYYY-MM-DD-task-slug-result.json`
