# Team Architectures

이 문서는 `revfactory/harness`의 팀 아키텍처 관점을 참고해, Codex 작업 저장소에서 쓸 수 있는 패턴으로 재구성한 안내서입니다.

핵심 생각은 단순합니다. 모든 작업을 한 명의 범용 에이전트에게 맡기지 말고, 작업 구조에 맞는 협업 패턴을 선택합니다.

## 패턴 목록

### 1. 파이프라인

순차 의존 작업에 적합합니다.

- 예시: 요구사항 정리 → 설계 → 구현 → 검증 → 문서화
- 장점: 책임 흐름이 명확하다
- 주의점: 초반의 오해가 뒤 단계로 전파되기 쉽다

### 2. 팬아웃/팬인

서로 독립적인 작업을 병렬로 나눈 뒤 결과를 다시 모읍니다.

- 예시: 보안 리뷰, 성능 리뷰, 테스트 설계, 문서 점검을 병렬 수행
- 장점: 속도가 빠르다
- 주의점: 최종 통합 기준이 없으면 결과가 충돌한다

### 3. 전문가 풀

문제 유형에 따라 다른 전문 역할을 선택 호출합니다.

- 예시: 프론트엔드, 백엔드, 데이터, 인프라, QA
- 장점: 불필요한 컨텍스트 낭비를 줄인다
- 주의점: 역할 경계가 흐리면 중복 작업이 생긴다

### 4. 생성-검증

무언가를 만든 뒤 별도 검증 루프로 품질을 확인합니다.

- 예시: 코드 생성 후 테스트, 린트, UI 확인, 로그 확인
- 장점: 빠른 생성과 엄격한 검증을 분리할 수 있다
- 주의점: 검증 기준이 모호하면 형식적인 리뷰가 된다

### 5. 감독자

중앙 조율자가 작업을 분배하고 결과를 합칩니다.

- 예시: 큰 기능 개발, 다중 영역 리팩터링, 복합 조사 작업
- 장점: 전체 목표와 우선순위를 유지하기 좋다
- 주의점: 감독자가 병목이 되면 오히려 느려진다

### 6. 계층적 위임

상위 작업을 더 작은 하위 작업으로 재귀 분해합니다.

- 예시: 대규모 마이그레이션, 모놀리스 분해, 장기 로드맵 실행
- 장점: 복잡한 문제를 단계적으로 줄일 수 있다
- 주의점: 하위 작업 간 계약이 불명확하면 통합 비용이 커진다

## 패턴 선택 가이드

- 작업 단계가 분명하고 순서 의존이 강하면 `파이프라인`
- 동시에 검토 가능한 독립 영역이 많으면 `팬아웃/팬인`
- 작업 종류가 다양하고 전문성이 갈리면 `전문가 풀`
- 결과 정확성이 특히 중요하면 `생성-검증`
- 큰 목표를 하나의 책임축으로 관리해야 하면 `감독자`
- 규모가 크고 단계적 분해가 필요하면 `계층적 위임`

## Codex 저장소에 적용하는 방법

이 저장소는 특정 멀티에이전트 런타임에 묶여 있지 않으므로, 패턴은 파일 구조와 작업 흐름으로 먼저 표현합니다.

- 계획 파일에 선택한 패턴을 명시합니다.
- 각 패턴에 맞는 역할을 `작업 브리프`로 쪼갭니다.
- 검증자는 구현자와 다른 체크리스트를 사용합니다.
- 교훈은 `HARNESS_EVOLUTION.md` 기준으로 다시 저장소에 반영합니다.

## 권장 산출물

- 실행 계획
- 역할별 작업 브리프
- 검증 체크리스트
- 최종 교훈 또는 진화 메모
