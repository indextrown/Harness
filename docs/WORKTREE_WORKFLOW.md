# Worktree Workflow

이 문서는 메인 작업 공간 대신 격리된 작업 공간에서 구현하는 흐름을 정의합니다.

## 왜 필요한가

- 메인 작업 공간을 직접 망가뜨릴 위험을 줄인다
- 변경마다 독립적인 실행과 검증을 할 수 있다
- 실패한 실험을 더 안전하게 버릴 수 있다

## 기본 원칙

- 가능하면 메인 브랜치에서 직접 구현하지 않는다
- 먼저 계획을 만든다
- 그 다음 격리된 작업 공간에서 구현한다
- 검증을 통과한 뒤에만 병합한다

## 권장 흐름

1. 작업 계획을 `docs/exec-plans/active/`에 만든다
2. 별도 워크트리 또는 별도 브랜치 작업 공간을 만든다
3. 그 작업 공간에서 구현과 테스트를 반복한다
4. 로그와 증거를 남긴다
5. 검증이 끝나면 메인으로 병합한다
6. 계획 파일을 `completed/`로 옮긴다

## 현재 저장소에서의 적용

이 저장소는 아직 Git 초기화가 되어 있지 않으므로, 실제 `git worktree` 명령은 아직 사용할 수 없습니다.

하지만 운영 원칙은 미리 문서화해 두고, Git을 붙인 뒤 바로 자동화할 수 있게 준비합니다.

## 자동화 후보

- 워크트리 생성 스크립트
- 메인 직접 수정 차단 훅
- 검증 통과 전 병합 차단 훅

현재 기본 명령:

- `scripts/create-worktree.sh`
- `scripts/check-worktree.sh`
