# Task Requests

이 문서는 `무엇을 하려는지`를 먼저 고정하는 작업 요청서 체계를 설명합니다.

## 왜 필요한가

계획 문서는 보통 `어떻게 할지`에 가깝습니다.

하지만 실제 작업을 시작할 때는 그보다 앞서 `무엇을 왜 하려는지`를 짧고 명확하게 적어두는 문서가 있으면 좋습니다.

작업 요청서는 다음 역할을 합니다.

- 작업 목표를 한 문서로 고정한다
- 구현 전에 범위와 완료 조건을 합의한다
- 계획 문서의 입력으로 사용된다
- 나중에 왜 이 작업을 했는지 되짚기 쉽다

## 작업 요청서와 실행 계획의 차이

- 작업 요청서: 무엇을 왜 하는가
- 실행 계획: 그것을 어떻게 구현하고 검증할 것인가

권장 흐름:

1. `docs/task-requests/active/`에 작업 요청서를 만든다
2. 필요하면 이슈를 만든다
3. `docs/exec-plans/active/`에 실행 계획을 만든다
4. 구현과 검증을 진행한다
5. 완료 후 요청서와 계획을 각각 정리한다

## 권장 규칙

- 큰 작업일수록 요청서를 먼저 만든다
- 요청서는 짧고 명확하게 유지한다
- 구현 세부보다 목표와 범위에 집중한다
- 작업이 끝나면 `completed/`로 옮긴다
