# PR Default Merge By Request

## 문제

작업 브랜치에서 커밋이 끝난 뒤 어디까지 자동으로 이어갈지 기준이 불명확하면, 어떤 때는 PR까지 가고 어떤 때는 중간에서 멈추게 된다.

## 제약 조건

- 원격 푸시는 이미 되어 있다는 전제가 있어야 PR 생성이 가능하다.
- PR 생성은 기본 흐름으로 삼을 수 있다.
- 병합은 더 파괴적이므로 사용자 명시 요청이 있어야 한다.

## 제안하는 접근 방식

1. 작업 브랜치에서 커밋과 원격 푸시가 끝나면, 특별한 이유가 없는 한 PR 생성까지 이어간다.
2. `merge`는 사용자가 명시적으로 요청했을 때만 실행한다.
3. 이 원칙을 `AGENTS.md`와 `docs/COMMANDS.md`에 반영한다.

## 검증

- `AGENTS.md`에서 작업 순서 규칙으로 읽히는지 확인한다.
- `docs/COMMANDS.md`에서 PR 생성과 병합의 기본 정책 차이가 드러나는지 확인한다.

## 의사결정 로그
