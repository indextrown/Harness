# Post Merge Branch Cleanup

## 문제

PR 병합 후 작업 브랜치가 원격이나 로컬에 남아 있으면 저장소가 빠르게 지저분해지고, 다음 작업 시작 지점도 흔들린다.

## 제약 조건

- GitHub PR 병합과 로컬 브랜치 정리는 함께 다뤄야 한다.
- 병합 후 로컬은 예측 가능한 상태여야 한다.
- 다음 작업은 항상 `main` 기준에서 시작하는 것이 안전하다.

## 제안하는 접근 방식

1. `scripts/merge-pr.sh`가 PR 병합 후 원격 브랜치 삭제를 요청한다.
2. 이어서 로컬 `main`으로 자동 이동한다.
3. 기존 작업 브랜치를 로컬에서도 삭제한다.
4. 이 규칙을 `AGENTS.md`와 `docs/COMMANDS.md`에 반영한다.

## 검증

- 명령 사용법이 새 인자를 설명하는지 확인한다.
- 병합 후 `main`으로 이동하는지 확인한다.
- 기존 작업 브랜치가 로컬에서 삭제되는지 확인한다.
