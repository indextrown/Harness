# Add Task Request Layer

## 문제

실행 계획 전에 `무엇을 할지`를 고정하는 별도 마크다운 층이 아직 없다.

## 제약 조건

- 기존 실행 계획 체계와 충돌하면 안 된다.
- 작업 요청서와 실행 계획의 역할 차이가 분명해야 한다.
- 명령 문서와 진입 문서에도 함께 반영되어야 한다.

## 제안하는 접근 방식

1. `docs/TASK_REQUESTS.md`를 추가한다.
2. `docs/task-requests/active/`, `completed/` 구조를 만든다.
3. 템플릿과 생성/완료 스크립트를 추가한다.
4. `AGENTS.md`, `README.md`, `docs/COMMANDS.md`에 반영한다.

## 검증

- 작업 요청서와 실행 계획의 역할이 문서상 구분되는지 확인한다.
- 스크립트가 인자 부족 시 사용법을 출력하는지 확인한다.
- 진입 문서에서 작업 요청서 체계로 접근 가능한지 확인한다.
