# Push By Request Rule

## 문제

작업 브랜치에서 커밋 이후 어디까지 자동으로 이어갈지 기준이 없으면, 원격 push까지 에이전트가 임의로 해버릴 수 있다.

## 제약 조건

- 원격 push는 외부 상태를 바꾸는 행동이다.
- 사용자가 원하지 않는 시점의 push는 협업 흐름을 어지럽힐 수 있다.
- PR 생성은 push 이후에만 가능하므로 두 단계를 구분해야 한다.

## 제안하는 접근 방식

1. 원격 push는 사용자가 명시적으로 요청했을 때만 수행한다.
2. 이미 push가 된 상태라면 특별한 이유가 없는 한 PR 생성까지 이어간다.
3. merge는 계속 사용자 명시 요청이 있을 때만 수행한다.

## 검증

- `AGENTS.md`에서 push 정책이 명확히 읽히는지 확인한다.
- `docs/COMMANDS.md`에서 push와 PR 생성 단계가 구분되는지 확인한다.
