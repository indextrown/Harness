# Issue PR Content Quality Rule

## 문제

이슈와 PR 생성 명령은 있지만, 템플릿 안내 문구가 그대로 남은 상태로 생성될 수 있다.

## 제약 조건

- 이슈와 PR은 실제 문제와 실제 변경 내용을 담아야 한다.
- 템플릿은 시작점일 뿐, 최종 내용이 되어서는 안 된다.
- 가능한 경우 스크립트 수준에서 막는 것이 좋다.

## 제안하는 접근 방식

1. 이슈/PR 템플릿에 작성 규칙을 명시한다.
2. `create-issue.sh`와 `create-pr.sh`가 기본 문구 잔존 여부를 검사한다.
3. `AGENTS.md`와 `docs/COMMANDS.md`에 구체 작성 원칙을 반영한다.

## 검증

- 기본 문구가 남은 body 파일로 생성 시 실패하는지 확인한다.
- 문서에서 구체 작성 원칙이 읽히는지 확인한다.

## 의사결정 로그

- 2026-04-28: 이슈와 PR은 실제 문제, 실제 변경, 실제 검증을 담도록 강제하기로 했다.
