# PR Merge Command Workflow

## 문제

PR 생성까지는 하네스 명령으로 표준화했지만, GitHub에서 실제 병합하는 단계는 아직 수동이다.

## 제약 조건

- GitHub CLI 로그인이 되어 있어야 한다.
- 병합 전략은 팀마다 다를 수 있으므로 선택 가능해야 한다.
- 로컬 병합과 GitHub PR 병합은 구분해야 한다.
- 병합은 사용자가 명시적으로 요청한 경우에만 실행해야 한다.

## 제안하는 접근 방식

1. `gh pr merge`를 감싼 스크립트를 추가한다.
2. `docs/COMMANDS.md`에서 PR 병합과 로컬 병합을 구분한다.
3. 리뷰 응답 메모 템플릿도 함께 추가한다.

## 검증

- 사용법이 출력되는지 확인한다.
- 머지 전략 인자가 검증되는지 확인한다.
- 문서가 `PR 생성 -> PR 병합` 흐름을 설명하는지 확인한다.

## 의사결정 로그

- 2026-04-28: PR 생성뿐 아니라 PR 병합도 하네스 명령으로 표준화하기로 했다.
- 2026-04-28: PR 생성은 기본 흐름으로 보되, 병합은 명시적 사용자 요청이 있을 때만 수행하기로 했다.
