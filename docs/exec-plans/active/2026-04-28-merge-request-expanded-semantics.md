# Merge Request Expanded Semantics

## 문제

사용자가 `merge해`라고 말할 때, 단순히 병합만 하라는 뜻인지 아니면 병합까지 가기 위한 커밋, push, PR 생성까지 포함한 뜻인지 기준이 필요하다.

## 제약 조건

- 평소에는 push와 merge를 명시 요청 기반으로 제한하고 있다.
- 하지만 `merge해`는 보통 최종 통합까지 마무리하라는 의도로 해석하는 편이 자연스럽다.
- 문서에 이 해석이 분명히 적혀 있어야 한다.

## 제안하는 접근 방식

1. `merge해`를 상위 요청으로 정의한다.
2. 필요한 경우 커밋, push, PR 생성, PR 병합까지 한 흐름으로 진행한다고 문서화한다.
3. `AGENTS.md`와 `docs/COMMANDS.md`에 이 해석을 반영한다.

## 검증

- `AGENTS.md`만 읽어도 `merge해` 해석 규칙이 보이는지 확인한다.
- `docs/COMMANDS.md`에 단계가 명확히 적혀 있는지 확인한다.

## 의사결정 로그

- 2026-04-28: `merge해`는 필요 시 커밋, push, PR 생성, 병합까지 포함하는 상위 요청으로 해석하기로 했다.
